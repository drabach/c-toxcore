Overview

The Tox Bootstrap Daemon (tox-bootstrapd) is a server-side application that provides essential infrastructure for the Tox P2P network. It's built on top of libtoxcore and serves as a bootstrap node - the first point of contact for new Tox clients joining the network.

Project Location: other/bootstrap_daemon/
Main Source: src/tox-bootstrapd.c

Purpose

The daemon serves three critical functions in the Tox network:

1. DHT Bootstrap Node

New Tox clients need to connect to the distributed network. The daemon maintains a DHT node that:

  • Stores peer contact information for the network
  • Responds to "get nodes" requests from new clients
  • Bridges new clients to existing network nodes

2. TCP Relay

For users behind restrictive firewalls (NAT, corporate networks), the daemon:

  • Acts as a TCP relay server
  • Forwards encrypted packets between peers
  • Enables connectivity when UDP is blocked

3. Onion Announcements

The daemon maintains onion service announcements:

  • Stores peer public keys and their associated curve25519 public keys
  • Allows friends to discover each other's presence
  • Enables the onion routing system for anonymous communication

Main Event Loop

int main(int argc, char *argv[])
{
    // 1. Parse command line arguments
    // 2. Load configuration file
    // 3. Initialize networking (IPv4/IPv6)
    // 4. Create toxcore components
    // 5. Main event loop:
    while (running) {
        mono_time_update(mono_time);
        do_dht(dht);                    // DHT processing
        do_gca(group_announce);        // Group announcements
        do_tcp_server(tcp_server);    // TCP relay
        networking_poll(net, NULL);   // Network I/O
        sleep_milliseconds(30);
    }
}

Component Initialization

// 1. Create networking core
Networking_Core *net = new_networking_ex(
    logger, mem, ns, &ip, start_port, end_port, NULL);

// 2. Create DHT
DHT *dht = new_dht(
    logger, mem, rng, ns, mono_time, net, true, enable_lan_discovery);

// 3. Create forwarding
Forwarding *forwarding = new_forwarding(
    logger, mem, rng, mono_time, dht);

// 4. Create announcements
Announcements *announce = new_announcements(
    logger, mem, rng, mono_time, forwarding);

// 5. Create group announces
GC_Announces_List *group_announce = new_gca_list(mem);

// 6. Create onion
Onion *onion = new_onion(
    logger, mem, mono_time, rng, dht);

// 7. Create onion announce
Onion_Announce *onion_a = new_onion_announce(
    logger, mem, rng, mono_time, dht);

// 8. Create TCP server (optional)
TCP_Server *tcp_server = new_tcp_server(
    logger, mem, rng, ns, enable_ipv6,
    tcp_relay_port_count, tcp_relay_ports,
    dht_get_self_secret_key(dht), onion, forwarding);

Component Details

DHT (Distributed Hash Table)

The core component implementing Kademlia-like peer discovery. Located at toxcore/DHT.h.

  • Ping interval: 60 seconds
  • Timeout: 5 seconds
  • Max nodes: 8 close to bootstrap
  • Fake friends: 2 (for onion path diversity)

Forwarding

Handles packet forwarding between peers in the network.

Announcements

DHT announcements for peer status - stores public keys and associated data.

Onion / Onion_Announce

Implements the onion routing system for anonymous communication paths.

  • Path length: 3 hops
  • Packet size: Max 1400 bytes

Group Announcements

Similar to DHT announcements but for group chat discovery.

TCP Server

TCP relay server for users behind firewalls.

  • Default ports: 443, 3389
  • File descriptor limit: 32768 recommended

Configuration

Configuration File Format

The daemon uses libconfig format:

// /etc/tox-bootstrapd.conf

pid_file_path = "/var/lib/tox-bootstrapd/tox-bootstrapd.pid";
keys_file_path = "/var/lib/tox-bootstrapd/keys";
start_port = 33445;

enable_ipv6 = true;
enable_ipv4_fallback = true;
enable_lan_discovery = false;
enable_tcp_relay = true;
enable_motd = false;

tcp_relay_ports = [ 443, 3389 ];

bootstrap_nodes = {
    {
        address = "127.0.0.1";
        port = 33445;
        public_key = "...";
    },
};

Installation

Systemd (Recommended)

# 1. Create dedicated user (security)
sudo useradd --home-dir /var/lib/tox-bootstrapd --create-home \
  --system --shell /sbin/nologin \
  --comment "Tox DHT bootstrap daemon" \
  --user-group tox-bootstrapd

# 2. Restrict home directory
sudo chmod 700 /var/lib/tox-bootstrapd

# 3. Copy config
sudo cp tox-bootstrapd.conf /etc/tox-bootstrapd.conf

# 4. Copy service file
sudo cp tox-bootstrapd.service /etc/systemd/system/

# 5. Enable and start
sudo systemctl daemon-reload
sudo systemctl enable tox-bootstrapd.service
sudo systemctl start tox-bootstrapd.service

# 6. Check status
sudo systemctl status tox-bootstrapd.service

Docker

# Pull official image
docker pull toxchat/bootstrap-node:latest

# Run with port mapping
docker run -d --name tox-bootstrapd --restart always \
  --user "$(id -u tox-bootstrapd):$(id -g tox-bootstrapd)" \
  -v /var/lib/tox-bootstrapd/:/var/lib/tox-bootstrapd/ \
  --ulimit nofile=32768:32768 \
  -p 443:443 \
  -p 3389:3389 \
  -p 33445:33445 \
  -p 33445:33445/udp \
  toxchat/bootstrap-node

# Check logs
docker logs tox-bootstrapd

Maintenance

Update Monthly! The DHT protocol may change between toxcore versions. Using an outdated daemon can cause connectivity issues for the entire network.

Status Check

systemctl status tox-bootstrapd.service
journalctl -f -u tox-bootstrapd.service

Retrieving Public Key

# From logs
sudo grep "Public Key:" /var/log/syslog

# Or read from keys file
sudo cat /var/lib/tox-bootstrapd/keys | xxd | head -2

Protocol Details

DHT Protocol

The daemon implements these DHT packet types (from DHT.h):

Packet IDDescription
CRYPTO_PACKET_FRIEND_REQ = 32Friend request
CRYPTO_PACKET_DHTPK = 156DHT public key
CRYPTO_PACKET_NAT_PING = 254NAT ping

Default Ports

  • UDP 33445 - DHT communication
  • TCP 443 - TCP relay (HTTPS)
  • TCP 3389 - TCP relay
