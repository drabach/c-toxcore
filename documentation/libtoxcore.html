Introduction

libtoxcore is the core C library implementing the Tox protocol - a peer-to-peer (P2P) secure messenger. The library provides a complete messaging stack including friend management, encrypted communications, file transfers, group chats, and audio/video calls.

Cryptographic Warning: This is an experimental cryptographic library. It has NOT been audited by independent cryptography experts. Use at your own risk. The security model is still being documented (see GitHub issue #210).

Architecture & Design Decisions

Design Principles

  1. No Central Servers - Pure P2P architecture using DHT for peer discovery
  2. End-to-End Encryption - All communications encrypted with NaCl/libsodium
  3. Minimal Dependencies - Only libsodium required; libvpx/opus optional
  4. Event-Driven - Callback-based event system for asynchronous events
  5. Single-Thread Friendly - Can run in single or multi-threaded mode

Events System

Toxcore uses a callback-based event system. Register callbacks to handle events:

Callback Registration Pattern

void tox_callback_{event}(Tox *tox, tox_{event}_cb *callback);

Available Event Callbacks

EventDescriptionCallback Signature

friend_message Received message void(Tox*, uint32_t, TOX_MESSAGE_TYPE, const uint8_t*, size_t, void*)
friend_connection_status Friend came online/went offline void(Tox*, uint32_t, Tox_Connection, void*)

Example: Setting up callbacks

// In main.c
static void handle_friend_request(
    Tox *tox,
    const uint8_t *public_key,
    const uint8_t *message, size_t length,
    void *user_data) {
    // Accept friend automatically
    TOX_ERR_FRIEND_ADD err;
    tox_friend_add_norequest(tox, public_key, &err);
}

static void handle_friend_message(
    Tox *tox,
    Tox_Friend_Number friend_number,
    Tox_Message_Type type,
    const uint8_t *message, size_t length,
    void *user_data) {
    // Echo back
    tox_friend_send_message(tox, friend_number, type, message, length, NULL);
}

int main(void) {
    Tox *tox = tox_new(NULL, NULL);
    
    tox_callback_friend_request(tox, handle_friend_request);
    tox_callback_friend_message(tox, handle_friend_message);
    
    while (running) {
        usleep(1000 * tox_iteration_interval(tox));
        tox_iterate(tox, NULL);
    }
}

Networking Layer

DHT (Distributed Hash Table)

The DHT provides serverless peer discovery using a Kademlia-like protocol:

  • Nodes - Store peer contact info (IP, port, public key)
  • Ping - Keep-alive messages every 60 seconds
  • Bootstrap - Connect to known seed nodes
// Bootstrap to network
tox_bootstrap(tox, "127.0.0.1", 33445, 
    (uint8_t[]){...}, NULL);

// Add TCP relay for firewall traversal
tox_add_tcp_relay(tox, "relay.tox.chat", 443, 
    (uint8_t[]){...}, NULL);

UDP vs TCP

  • UDP - Direct peer-to-peer, lower latency
  • TCP - Via relays, works through firewalls

Messenger Plugins

Extend Messenger to save custom state across sessions:

// Define plugin
static uint32_t my_state_size(const Messenger *m) {
    return sizeof(MyState);
}

static uint8_t *my_state_save(const Messenger *m, uint8_t *data) {
    MyState *s = (MyState *)data;
    s->value = m->my_value;
    return data + sizeof(MyState);
}

static State_Load_Status my_state_load(
    Messenger *m, const uint8_t *data, uint32_t length) {
    memcpy(&m->my_value, data, sizeof(MyState));
    return STATE_LOAD_STATUS_OK;
}

// Register
Messenger_State_Plugin plugin = {
    .type = STATE_TYPE_CUSTOM,
    .size = my_state_size,
    .save = my_state_save,
    .load = my_state_load
};
messenger_register_state_plugin(messenger, &plugin);
